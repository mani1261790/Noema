## なぜこの方向にしたか

### 目的・出口
- **収益化はしない**。狙いは **OIFの認知向上とOIFへの流入**。
- 併せて**後継者育成**：現運営（1年次から仲の良いB2 4人）の卒業後も組織が回るよう、既存メンバーと同じ深さでAIを理解する人を増やす。
- 教える工数を減らすため、**自走支援**（自分で学び進められる導線）を重視する。

### ターゲットを2階層にした理由
> 公開UIの分類（`approach` = experience/practice/development/theory）と情報設計は [content-strategy](./content-strategy.md) を正とする。以下はその背景となった議論。

- **入口層（認知・流入）**：AIにまだ深く触れていない層（意識高い系の文系など）。ChatGPT・NotebookLM・Claude Design等のライトツールを、ブログ的・直感的に。
  - 具体的な受け皿：起業部AIコーディング課（在籍10名だが実装できる人がおらず停滞中）、今後増える「AIをやりたい文系層」。
  - 狙い：「AIの有用性を見つけられず挫折する人」に、目に見えてすごいものを作れる体験を先に渡す。
- **次のステップ層（深化・後継者育成）**：入口層で興味を持ち、既存メンバーと同じ深さまで進みたい人。最先端開発環境〜基本開発ツール〜Python/Next.js〜LLM・拡散モデルの仕組み〜NN・機械学習・統計。
  - 締切なしの継続タスク。理論部隊が各自独立して構成してよい。体系化は難しいので**「すごいと思われそうな内容」から優先着手**する。

### 差別化の狙い
- 全体像・行間を埋める（GCI等の既存教材で説明されない部分）。
- コードは手段であり目的ではない（データサイエンス・実装コード自体を主眼にしない）。
- 記事を読む感覚で直感的に理解できる。AIツールから入って仕組みへ進む構造。
- 起業部・文系からのフィードバックを取り込める。
- スタイル参考：高校数学の美しい物語、こんとろラボ（直感的・ブログ的な解説）。

### MTGで確定した前提（詳細仕様は別docへ）
- インフラは AWS でなく **Cloudflare**（軽量・運用コスト低・学生体制向き）。→ 構成は [product-reboot §7](./product-reboot.md)。
- LLMに聞ける機能は**読者自身のAPIキー入力方式**（Noema側でAPIコストを負担しない）。→ [product-reboot §6](./product-reboot.md)。
- コンテンツ運用は**各自がMDで貯め、溜まったら配置・整形**。→ 執筆・配置は [product-reboot §4–5](./product-reboot.md)。
- 旧AWS版は**完全退役・アーカイブ化**（MTG時点の「mainは稼働維持」から変更）。→ [Noema AWS Archive](https://github.com/mani1261790/Noema-AWS-Archive)。
