# サービス方針MTG記録（夏NOEMA）

> **決定日**: 2026-07-10 / **最終更新**: 2026-07-13
> **正本**: Notion「夏NOEMAとサービス開発MTG」（OIF 運営ハブ配下）。本ドキュメントは開発リポジトリ側で共有するスナップショット。
> **位置づけ**: Noema をなぜ現在の形に作り直したかの背景・意思決定記録。実装仕様は [product-reboot](./product-reboot.md) / [content-strategy](./content-strategy.md) を正とする。

## 目的・出口
- **収益化はしない**。目標は **OIFの認知向上とOIFへの流入**。
- 併せて**後継者育成**が狙い：現運営（1年次から仲の良いB2 4人）が卒業した後も組織が回るよう、既存メンバーと同じ深さでAIを理解する人を増やす。
- 教える工数を減らすため、**自走支援**（自分で学び進められる導線）を重視する。

## ターゲット・構造（2階層）

### 入口層（認知・流入）
- 対象：意識高い系の文系など、AIにまだ深く触れていない層
- 内容：ChatGPT・NotebookLM・Claude Design等のライトツール。ブログ的に、直感的に理解できる形で。
- 受け皿になり得る層：起業部AIコーディング課（在籍10名・実装できる人がおらず停滞中）、AIをやりたい文系層（今後も増加見込み）
- 狙い：「AIの有用性を見つけられず挫折する人」に、目に見えてすごいものを作れる体験を先に提供する

### 次のステップ層（深化・後継者育成）
- 対象：入口層で興味を持ち、既存OIFメンバーと同じ深さまで進みたい人
- 内容：Codex・Obsidian・Hermes Agent等の最先端開発環境／Terminal・Git・Vercel・DB等の基本開発ツール／AWS・GCPのさわり／Python・Next.js／ローカルLLM・LLM・拡散モデルの仕組み・画像処理・NLP／ニューラルネットワーク・機械学習・統計
- 締切なし。継続的に蓄積していく運営の継続タスク（理論部隊が各自独立して自由に構成してよい）
- 体系化は難しいと認識した上で、**「すごいと思われそうな内容」から優先着手**する
- スタイル参考：高校数学の美しい物語 等（直感的・ブログ的な解説）

## 差別化ポイント
- 全体像・行間（GCI等の既存教材で説明されない部分を埋める）
- コードは手段であり目的ではない（データサイエンス・実装コード自体は教材の主眼にしない）
- 記事を読む感覚で直感的に理解できる
- AIツールから入って仕組みに進む構造
- 起業部・文系からのフィードバックを取り込める

## 開発方針（MTG時点の決定）
- 収益化なし・フルスタックの自作基盤は不要
- インフラは AWS でなく **Cloudflare**（軽量・運用コスト低・学生体制向き）
- 現行Noemaは大幅改修する（0から作り直す）。→ 実際は **旧AWS版は完全退役・アーカイブ化**した
- コンテンツ運用：**各自がMD形式で教材を貯めていき、ある程度溜まったら配置・整形**する
- 参考：[デジタル庁ホームページ](https://www.digital.go.jp/)（情報設計・見やすさ、蓄積→配置の仕組み）
- LLMに聞ける機能は**ユーザー自身のAPIキー入力方式**（Noema側でAPIコストを負担しない）
- 配置エンジン（貯まったMDを整形・表示する部分）の実装：Mani

## 実装状況（2026-07-13時点）

> MTG（7/10）の決定後、実装を進行。**基盤はすでに稼働している**。詳細な仕様・デプロイ手順は [development-deployment](./development-deployment.md) を参照。

### プロダクトの姿（再定義済み）
- Noema = **独立した技術メディア（Markdownブログ）**。旧notebook学習サービス（ipynb・採点・進捗・Python実行）は廃止。
- 3本柱：①公開ブログ ②Markdown執筆Studio ③記事アシスタント（表示中の記事だけを文脈にLLM質問／**読者自身のAPIキー**、Noema側は鍵を保存しない）
- 編集方針上、NoemaはOIFの勧誘サイトにしない。OIFはAboutページの運営情報からのみ案内する。

### 技術構成
- **Cloudflare Workers**（AWSから移行済み）。モノレポ `vnext/` に4アプリ：ブログ（Astro）／Studio（React + Vite）／公開ゲートWorker／共通UI・contentパッケージ。
- 旧AWS実装（CDK・Lambda・DynamoDB・Cognito等）は退役し、復元手順ごと `Noema-AWS-Archive` リポジトリに保存済み。
- UIは**デジタル庁デザインシステム（DADS）準拠**。適合状況は [DESIGN_CONFORMANCE](../vnext/DESIGN_CONFORMANCE.md) で管理。

### コンテンツ運用
- 記事は内部メタデータ `approach`（experience / practice / development / theory）で管理し、トップのカード配置が決まる。**難易度ではなく「技術への入り角度」**。体験・活用は大カード、開発・理論は小カード。公開UIにレベル表記は出さない。
- 執筆導線：Studioで書く or リポジトリにMDを置く → PR → `develop` → 自動反映。

### いまのボトルネック
- **実装は先行、コンテンツがゼロ**。記事ディレクトリは空で、開発preview上に出るのは確認用fixtureのみ。次の律速は明確に**執筆**。

## スケジュール
- **MVPは8月中に構築、9月リリース**（基盤は前倒しで7月時点に到達済み。残りは記事）
- MVPスコープ = 入口層の内容 ＋ MD蓄積・配置の仕組み（軽量版）。次のステップ層の深いコンテンツはMVPの締切に含めない
- 期末テストまでは各自多忙なため、本格着手はテスト終了後

## 未決事項（次回MTGで詰める）
1. UI・構造の方向性 → **解決済み**（DADS準拠・カード配置ルールまで実装）。残るのは**執筆側の役割分担と権限**（誰がどのテーマを何本書くか、Studioの権限設計）
2. 9月リリース時の**記事ラインナップと本数**（最低何本必要か／approach別の配分）
3. コンテンツ候補を「入口層」「次のステップ層」に仕分けする作業（棚卸しのみで未着手）
4. Mani以外の担当分について「8月末までに何を出すか」の明示合意
5. **公開ゲートを外す条件**（`noema-learn.uk` を開ける判断基準と時期）
6. 【要修正】Aboutページの運営主体表記が「OIF（Open Innovation Foundation）」になっている。正しくは **OMU Innovation Frontier**
