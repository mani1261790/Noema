# 読者画面の余白・レスポンシブ監査

## 修正

- ホームのテーマ一覧は、背景付きカードへ変更した後も旧リストの `row-gap: 0` が残っていた。縦横24px、640px以下では12pxに変更。
- スマホの読む目的別カードの間隔を8pxから12pxへ変更し、シリーズ・テーマとそろえた。
- スマホのテーマセクションの上下余白を72pxから24pxへ変更し、他のホームセクションとそろえた。
- 新着記事の4列構成では、日時とテーマがタイトル幅を圧迫していた。メタデータを上段にまとめ、タイトルを広く表示する。スマホでは「記事を読む」をその下へ配置する。
- シリーズ概要の共有欄は、記事一覧の下へ移動した際の `margin-top: 0` が残っていた。全幅で32pxの間隔を確保。

## 確認範囲

修正前のdevelop公開環境で、ホーム、記事検索、シリーズ一覧・概要、テーマ、記事本文2種類、執筆者、運営について、プライバシー、利用条件、更新案内、インストール、404の14ページを320/390/768/1160pxで確認（56ケース）。全ページで水平オーバーフローなし。404ページ以外は200。390/768pxの全ページキャプチャを取得し、主要一覧と案内ページを目視確認した。

さらに公開記事50本を320pxで巡回。すべて200、水平オーバーフローと読み込み完了済み画像の破損はなし。閉じたシリーズ紹介の最大高さは163.5px。これは読み込み途中・遅延読み込み画像をすべて取得したことを保証する検査ではない。

修正後のローカルbuild + Wranglerで、320/390/640/641/768/1024/1160pxのホーム、展開した検索フィルター・AI案内、記事質問パネル、該当幅のモバイルメニューを確認。740×320pxの横向きメニューも確認。水平オーバーフロー・表示中の操作要素の横方向のはみ出しなし。テーマの実測gapは12/24px。768pxで新着タイトルの幅は618px。

ローカルの記事データは公開HTMLから再構成した確認用データであり、CMSの正本ではない。公開データの確認と区別する。画面はChromiumでのシミュレーションであり、iPhone実機確認ではない。

`pnpm --dir vnext --filter @noema/blog check`、`build`、`git diff --check` を実施。CSSとマークアップの変更は実ブラウザーで確認し、実装値を複製するだけの単体テストは追加していない。

キャプチャと巡回結果は作業ツリーの `output/playwright/` に保存（Git追跡外）。公開環境の最終確認結果はPRに記録する。

## 追加の拡大・状態確認

文字を200%へ拡大すると、共有CSSの `body { min-width: 20rem }` が640pxになり、390pxの画面からはみ出すことを発見。読者画面の最小幅を解除し、ヘッダー・テーマ見出し・シリーズへのリンクを折り返せるようにした。320/390pxの7ページ（ホーム、記事検索、シリーズ一覧・概要、記事、運営案内、更新案内）を200%文字サイズで確認した。

検索0件表示とJavaScript無効時の検索フィルター開閉も確認。シリーズ末尾と共有欄の実測間隔は32px。

拡大時の展開メニューが画面高を超える場合には、ヘッダー内を縦スクロール可能にした。200%文字サイズでメニュー内の検索入力へ移動し、`Git` を入力して検索結果へ遷移できることを確認。
