# Noemaコンテンツ・掲載方針

ステータス: 決定済み・現行実装基準

決定日: 2026-08-26

## 1. 目的

Noemaは、AIでできることと、その仕組みを、直感と具体例からひもとく独立した技術メディアである。「なんとなく面白そう」という関心から単独の記事へも入れ、ひとつのテーマを深めたいときはシリーズを順番にたどれるようにする。

運営背景にはOIFがあるが、NoemaをOIFの勧誘サイトとして設計しない。Noema自身の内容と編集方針を前面に置き、OIFはAboutページの運営情報からのみ案内する。

## 2. 想定読者

- AIに関心はあるが、数式、コード、Terminalから始めると読みづらい人
- 技術が仕事や生活にどう関係するかを先に知りたい人
- 道具を使う話、何かをつくる話、仕組みの話を関心に応じて読みたい人
- 正確さを失わず、平易な説明を読みたい技術者

## 3. 公開画面の情報設計

- Level、記事タイプ、到達目標、前提知識を公開UIの分類ラベルとして表示しない。
- 公開導線の主軸はシリーズとする。トップページではシリーズを先に、新着記事を次に示す。
- シリーズに属さない記事も記事一覧と検索から読めるようにする。シリーズは唯一の入口ではない。
- トップページの掲載順を「注目」と呼ばない。公開日の新しい記事を、編集上の推薦と誤認させない。
- 記事カードはテーマ、タイトル、要約、日付を同じ階層で示し、編集用分類によって大きさや色を変えない。
- 記事一覧ではキーワードを主操作とし、シリーズ、テーマ、タグを詳細条件として使えるようにする。
- 読者へ制作工程、公開予定、執筆体制を説明する文言を通常画面に置かない。
- 記事がない場合は「記事はまだありません」とだけ示す。

## 4. 編集用分類

記事の配置判断には次の内部メタデータを使う。これは編集用であり、公開画面へ名称を表示しない。

```yaml
approach: "experience" # experience | practice | development | theory
outcome: "編集時に確認する記事の狙い"
prerequisites: []
topics:
  - "research-organization"
tags:
  - "NotebookLM"
```

| `approach` | 編集上の扱い |
| --- | --- |
| `experience` | 初めて触れる人にも届く体験記事 |
| `practice` | 日常や制作へ広げる記事 |
| `development` | 開発環境や実装を扱う記事 |
| `theory` | AIや数理の仕組みを扱う記事 |

`approach`は難易度ではなく、記事が技術へ入る角度を表す。`development`と`theory`は上下関係ではなく同格とする。Codexの体験記事はTerminalやGitを前提にしない。

`approach`を公開カードの大きさや色へ変換しない。読者が知りたいのは編集分類ではなく、何を読めて、どこまで進めるかである。

## 5. シリーズとカード表現

- シリーズは、複数の記事を順番に読むことでひとつの理解へ到達できるまとまりとする。
- シリーズカードには、説明、公開中の記事数、冒頭の記事を示す。カード全体をひとつのリンクにする。
- 個別シリーズページでは、公開中の記事だけをCMSの並び順で示す。
- 記事上部では、記事単体の到達目標を先に示す。その後にシリーズ名と現在位置をコンパクトに示し、全体の並びは閉じた状態から確認できるようにする。
- 記事末尾では前後の記事へ移動できるが、単独の記事として読むことも妨げない。

- 記事カードは白背景、1pxの四辺外周とし、ページ内で一貫した大きさと角丸を使う。
- カード全体を1つのリンクとし、カード内に別のリンクや操作を置かない。
- タイトルリンクは常時下線付きにし、リンクであることを色だけに依存させない。
- hoverとfocusはNoemaのキーカラーで統一し、分類色に意味を持たせない。

## 6. テーマとタグ

テーマは「何について書かれた記事か」を表す検索用の補助情報とする。サイトのトップ階層には固定テーマ一覧を置かず、記事一覧の絞り込みと関連記事の発見に使う。現行のテーマ名はコンテンツの増加に応じて統廃合できるものとし、サイト構造そのものにはしない。

1. 対話AI（`conversational-ai`）
2. 情報検索・整理（`research-organization`）
3. 生成・制作（`generation-creation`）
4. 開発環境（`development-environment`）
5. データとモデル（`data-models`）
6. 数理（`mathematics`）

ChatGPT、NotebookLM、Codex、Obsidian、Python、Cloudflare等の製品名・技術名はタグとして管理する。

例えばNotebookLMの体験記事と検索・埋め込みの理論記事は、記事タイプが異なっても同じ「情報検索・整理」テーマに配置できる。

## 7. CMSの公開範囲

記事のreview状態とpublication状態は、読者向けの公開範囲とは別に管理する。review中、未公開、保管の記事は公開範囲の設定にかかわらずブログへ出さない。

| 公開範囲 | 一覧・検索・テーマ・RSS・sitemap | 直接URL | 用途 |
| --- | --- | --- | --- |
| `public` | 掲載する | 閲覧可能 | 通常の公開記事 |
| `unlisted` | 掲載しない | 閲覧可能 | URLを知る人だけへ共有する記事 |
| `restricted` | 掲載しない | 読者認証後だけ閲覧可能にする予定 | 指定メンバー向け。現在は公開不可 |
| `internal` | 掲載しない | 公開ブログでは閲覧不可 | 運営メンバーだけがStudioで扱う原稿 |

`unlisted`は認証や秘密保持の境界ではない。slugを知る人は閲覧できるため、個人情報、機密情報、有償コンテンツには使用しない。`restricted`は読者認証が未接続であり、CMSは現在この範囲での公開操作を拒否する。

一般公開から限定URLへ変更する場合も、承認済みrevisionを管理者が再公開する。公開中の記事を編集しただけではpublished revisionや公開範囲を変更しない。

## 8. NoemaとOIFの関係

- Noemaの名称、編集方針、閲覧体験を最優先する。
- ヘッダー、記事カード、記事末尾にOIFの勧誘CTAを置かない。
- OIFへのリンクはAboutページ内の運営情報から`https://oif-ai.com`へ張る。
- 記事分類をOIFの組織構成として説明しない。

## 9. 受入条件

- 公開画面にLevelや記事タイプが表示されない。
- トップページ、ヘッダー、記事ページからシリーズへ移動できる。
- シリーズページには公開中の記事だけがCMSの順番どおりに表示される。
- シリーズに属さない記事も記事一覧と検索から読める。
- 記事カードの大きさや色が`approach`によって変わらない。
- キーワード、シリーズ、テーマ、タグから記事を探せる。
- 記事には執筆者、公開日、更新日、参考資料と確認日を表示できる。
- 記事末尾から、シリーズの前後記事、テーマやタグが共通する記事へ移動できる。
- 制作工程や運営都合を説明するメタ的な文言が公開画面にない。
- OIFへの外部リンクはAboutページだけにある。
- 一般公開記事と、それを1本以上含むシリーズだけが一覧、検索、テーマ、RSS、sitemapに掲載される。
- 限定URL記事は直接URLでだけ閲覧でき、`noindex`となる。
- 指定メンバー記事と運営メンバー限定記事が公開ブログから取得できない。
