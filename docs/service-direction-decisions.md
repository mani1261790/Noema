# Noemaサービス方針の意思決定記録

- 決定日: 2026-07-10
- 公開用整理: 2026-08-12

この文書は、Noemaを現在の独立した技術メディアへ再設計した背景を残す。実装仕様や運用手順ではなく、後から設計を見直すときに「なぜこの方向を選んだか」を確認するための記録である。

## 1. 目指すもの

Noemaは収益化を目的とせず、AIでできることと仕組みを、直感と具体例から理解できる技術メディアを目指す。入口で興味を持った人が、他者から継続的に教わらなくても、自分で次のテーマへ進める状態を作る。

運営母体の活動や人材育成へ成果が還元されることは期待するが、Noemaを組織への勧誘サイトにはしない。公開面ではNoema自身の内容と編集方針を主役にし、運営情報はAboutページへ分離する。

## 2. 想定読者を2層で捉えた理由

### 興味を持つ入口にいる人

AIへ関心はあるものの、学ぶ理由や具体的な使い道をまだ見つけられていない人を想定する。最初から体系的な学習順序を課さず、身近なツール、目に見える成果、気になる話題から入れるようにする。

### 仕組みまで理解したい人

入口で得た関心を、開発環境、プログラミング、LLMや生成モデルの仕組み、機械学習や統計へ深めたい人を想定する。記事は一つの順路へ固定せず、読者が関心に応じて必要な深さを選べる構成にする。

この2層は会員区分やCMS上の分類ではない。公開UIの分類と記事の掲載方法は、[コンテンツ・掲載方針](./content-strategy.md)を正とする。

## 3. コンテンツ設計で重視すること

- コードやツールの操作自体を目的にせず、それらで何ができ、なぜ動くかをつなげる。
- 既存教材が省略しがちな全体像や前提を補い、専門知識の手前にある疑問を置き去りにしない。
- 正確さを保ちながら、記事として読み進められる直感的な説明を優先する。
- 初学者からのフィードバックを、題材選びと説明の改善へ戻す。
- 網羅性を先に求めず、読者が価値を実感しやすい題材から公開して改善する。

## 4. 当初案から変更した判断

2026年7月10日の会議後、試作と運用設計を進める中で、次の判断を更新した。

| 当初案 | 現在の判断 | 変更理由 |
| --- | --- | --- |
| 各執筆者がMarkdownファイルを貯め、まとめて配置・整形する | StudioからCloudflare D1のCMSへ保存し、レビュー・承認・公開する | 複数人編集、版管理、公開中の記事の安全な更新、権限管理を一つの流れで扱うため |
| 記事公開をGitHub Draft PRと連携する | 記事公開はStudio内で完結し、GitHubはコード、schema、docsを管理する | 執筆者に開発用GitHub操作を要求せず、記事とアプリケーションのリリースを分離するため |
| 旧AWS版を維持しながら新構成を検討する | 旧AWS版を退役・公開アーカイブ化し、Cloudflare構成へ移行する | 学生主体の運営で、費用と保守対象を抑えながら継続できる構成にするため |

現在の構成、制約、未決定事項は[プロダクト再設計仕様](./product-reboot.md)を参照する。この文書へ進捗状況や一時的なTODOは記載しない。
