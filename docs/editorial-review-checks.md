# 記事の自動警告とMCP校正記録

Studioのレビュー画面・入力チェックと、MCPの検証・プレビュー・保存・レビュー依頼で、通常文字の数式、textコード枠の数式、タイトルの連番、既存の参考見出し警告を表示します。数式は行番号、連番はタイトル欄へ移動できます。

警告は確認の候補です。コードの代入や製品名などを誤って変更しないよう、これらの警告だけではレビューを止めません。数式の数学的な正しさ、テーマの主題との適合、日本語の読みやすさは、警告の件数では判定しません。参考資料の自動削除や、公開済み記事の書き換えも行いません。

## MCP保存の必須条件

`studio_create_draft`、`studio_update_draft`、`studio_restore_article_version` は `proofreading` を必須とします。

1. 投稿する内容を `studio_validate_draft` に渡します。`proofreadingTarget.text` と `proofreadingTarget.sha256` が返ります。
2. `text` を、末尾の改行も含めUTF-8ファイルへそのまま保存します。タイトル・要約・狙い・分類・画像の説明・本文・参考資料が対象です。CMSが計算する更新日・読了時間・前提知識は対象外です。
3. human-writingの指示で確認・編集し、yomiyasuで推敲します。修正を記事の各欄へ反映し、再度 `studio_validate_draft` を呼び出します。本文だけを検査しても、対象全体のハッシュは一致しません。
4. 最終的に返る `text` に対してyomiyasuの `run` と `verify` を実行し、指摘と意味の変化を確認します。書き換えでは `lint`・`diff`・`verify`、新規作成では `lint`・`materials`・`verify` が必要です。検査候補0件を合格条件にはしません。
5. `studio_preview_draft` で記事を確認してから、次の記録を投稿時に添えます。スキルのバージョン番号がない場合は、利用した指示の版を識別できる日付やコミットを使います。

```json
{
  "humanWriting": {
    "version": "利用したスキルの版",
    "notes": "想定読者、段落の役割、具体性、留保などの確認内容"
  },
  "yomiyasu": {
    "version": "利用したスキルの版",
    "runId": "検査記録の実行ID",
    "finalSha256": "最終稿の完全なSHA-256（小文字の16進数64桁）",
    "mode": "rewrite",
    "checks": ["lint", "diff", "verify"],
    "findingsReviewed": true,
    "notes": "指摘への対応と、意味が保たれているかを確認した内容"
  }
}
```

`finalSha256` はyomiyasuが実際に照合したファイルのハッシュです。画面の短縮ハッシュではなく完全な値を使います。`proofreadingTarget.sha256` を実行せずに転記してはいけません。投稿後の記録は記事詳細の `proofreading`、必須条件は `proofreadingRequired` で確認できます。保存した記録の時刻と申告者は、そのrevisionの作成日時・作成者です。

版を復元するときも、取得した過去版の内容を `studio_validate_draft` に渡して再確認し、記録を添えます。保存は常に新しいrevisionです。`expectedVersion`、`requestId` の既存の競合検知・再送処理はそのまま使います。

## Studio編集後と既存記事

MCP経由で一度でも作成・更新した記事には、校正必須の条件を保持します。Studio画面で編集や復元をすると、元の記録を新しい版へ自動では引き継ぎません。最新版をMCPで再校正・保存してからレビューを依頼します。レビュー依頼・承認・公開はCMS共通処理で記録を再確認します。画面から呼んでも回避できません。

migration `0026_article_proofreading.sql` は既存の作成・更新の監査イベントからMCP記事を識別します。既存の公開版を変更したり公開を取り下げたりはしません。該当記事が次にレビュー・承認・公開へ進むときには新しい記録が必要です。移行前から承認済みの場合は、一度承認を取り消して校正・保存します。MCP経由の履歴がないStudio手動記事へのスキル必須化は行いません。

## 保証する範囲

サーバーは記録の形式、必要な検査の申告、対象原稿のSHA-256との一致を検証し、revisionと一緒に保存します。編集者が申告した実行記録であり、端末上で本当にスキルを実行したことの暗号学的な証明ではありません。Studioにもこの区別を表示します。

実行そのものをサーバーで保証するには、信頼された校正実行サービスと署名済み結果の検証が別途必要です。今回、外部LLM呼び出しや有料実行サービスは追加しません。スキルを使えないクライアントはMCP保存を完了できません。
